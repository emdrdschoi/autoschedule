# 자동스케쥴 작성기
** 3교대 D(낮) / E(저녁) / N(밤) 근무표**를 자동으로 만드는 도구입니다.  
---

## 1. 가장 먼저 알아둘 것

스케줄러는 규칙을 크게 두 종류로 나누어 생각합니다.

### 반드시 지켜야 하는 조건
아래 조건을 모두 만족시키는 스케쥴을 생성합니다

예:
- Duty별 D / E / N 의 **Minimal duty requests로 정의합니다**
- 연차, 근무불가일
- 개인별 고정 총근무수 
- 최대 근무수
- 최소 / 최대 N근무수
- N 후 휴무일수 
- 연속 N 의 갯수
- 최대 연속 근무일수, 1주일 내 최대 근무일수
- Grade별 필수 인원

### 가능하면 맞추는 권장사항
스케줄은 만들 수 있지만, 가능한 범위에서 더 좋은 배치를 찾을 때 사용합니다.

예:
- Duty별 최소 필요인원 수를 만족하고도, 구성원의 근무수가 초과 할 경우 Duty의 초과 배정 **Ideal duty로 정의합니다**
- 저년차가 한 Duty에 너무 몰리지 않도록 분산
- 구성원 간의 D/E/N, 휴일, 총근무수의 균형 등 

---

## 2. 스케줄러가 근무수를 정하는 핵심 원칙

### 모든 구성원에게 `고정 총근무수`를 입력한 경우

전체 고정 총근무수의 합이 **이번 달 전체 근무수**가 됩니다.

1. 듀티별 **최소 인원**을 먼저 반드시 채웁니다.
2. 고정 총근무수 때문에 최소 인원보다 더 많은 근무가 필요하면 그 근무를 추가합니다.
3. 추가근무는 **Ideal을 입력한 Duty를 우선** 채웁니다.
4. 한 날짜나 한 Duty에 너무 몰리지 않도록 가능한 범위에서 분산합니다.
5. 마지막으로 N, D/E, 휴일, Grade 등의 균형을 다듬습니다.

**Ideal을 크게 입력했다고 해서 전체 근무수가 새로 늘어나지는 않습니다.**

### 고정 총근무수가 비어 있는 구성원이 있는 경우

1. 고정 총근무수가 있는 사람은 그 숫자를 **정확히** 지킵니다.
2. 날짜별 최소 인원을 채우기 위해 더 필요한 근무는 **고정 총근무수가 없는 사람**에게 배정합니다.
3. 개인별 최대 근무수, N 범위, 연차, 근무 패턴과 전체 균형을 함께 고려합니다.
4. 추가 배치 위치를 정할 때 Ideal duty requests 입력된 값이 있으면 그쪽을 우선 고려합니다.

### 고정 총근무수가 모두 비어 있따면

1. 모든 구성원들에게, duty 설정의 최소 D/ E/ N 을 배정합니다, Ideal 은 사용하지 않습니다.
2. 개인별 최대 근무수, N 범위, 연차, 근무 패턴과 전체 균형을 함께 고려합니다.


---

## 3. 빠른 사용 순서

1. **간호사 관리**에서 이름을 추가합니다.
2. **근무 요청 / 날짜 설정**에서 연차와 근무 가능·불가능 요청을 입력합니다.
3. **Duty 설정**에서 날짜별 최소 D/E/N 인원을 입력합니다.
4. 필요하면 주황색 **Ideal D/E/N**을 입력합니다.
5. **개인 규칙 / Grade**에서 월 근무수, N근무 범위와 근무 패턴을 설정합니다.
6. 이전 달과 연결되는 스케쥴표가 있다면 **직전 5일 스케줄**을 입력합니다.
7. 화면 위의 **필수 규칙 사전검사**를 확인합니다.
8. **스케줄 생성**을 누릅니다.

---

## 4. Duty 설정

### 최소 인원

`최소 D / 최소 E / 최소 N`은 그 날짜에 **반드시 필요한 최소 인원**입니다.  
`0`을 입력하면 해당 Duty는 닫혀서 아무도 배정하지 않습니다.

### Ideal 인원

Ideal은 **추가근무가 생겼을 때 우선적으로 채우고 싶은 인원수**입니다.

예: 최소 D = 7, Ideal D = 8  
→ D에 추가 인원을 배치해야 할 때 8명까지 채우는 것을 선호합니다.

Ideal은 화면에서 **주황색**으로 표시되고 `+ / −`로 조절할 수 있습니다.  
빈칸이면 해당 날짜/Duty의 Ideal을 사용하지 않습니다.

**Ideal은 전체 근무수를 증가시키는 명령이 아닙니다.** 이미 필요한 추가근무의 위치를 정하는 기준입니다.

---

## 5. 월 근무수 설정

| 화면 항목 | 의미 | 빈칸이면 |
|---|---|---|
| **고정 총근무수** | 월 D+E+N 총근무수를 정확히 고정 | 자동 배정 |
| **최대 근무수** | 월 총근무수가 이 숫자를 넘지 않음 | 제한 없음 |
| **최소 N근무수** | N을 최소 이만큼 배정 | 최소 제한 없음 |
| **최대 N근무수** | N을 최대 이만큼 배정 | 최대 제한 없음 |
| **고정 D / E / N** | 해당 근무의 정확한 월 개수 | 자동 배정 |
| **근무조정값** | 자동배정 대상자의 근무수를 조금 늘리거나 줄이는 보조값 | 보통 0 사용 |

예: `고정 총근무수=18`, `최소 N근무수=3`, `최대 N근무수=5`  
→ 총 18근무를 정확히 배정하면서 N은 3~5개가 되어야 합니다.

`고정 N=4`이면 N은 정확히 4개입니다.

---

## 6. 근무 요청 기호

- **대문자 D / E / N**: 반드시 해당 근무
- **소문자 d / e / n**: 해당 근무 불가능
- **x**: 근무 불가
- **a**: 연차
- 빈칸: 특별한 요청 없음

대문자 요청이나 연차는 필수 규칙으로 취급되므로 다른 규칙과 충돌하면 사전검사에서 표시됩니다.
소문자로 된 요청은 중복하여 기재할 수 있습니다 ( ** de = day, evening 근무는 불가능 ** )

---

## 7. 개인 근무 패턴 규칙

각 규칙 이름에 마우스를 올리면 자세한 설명을 볼 수 있습니다.

- **하루 최대 근무 종류 수**: 보통 1
- **연속 N 최대** : 2이면 NN 까지 가능합니다
- **N 종료 후 반드시 쉬는 날**
- **N 종료 후 다음 N까지 간격**
- **E 다음날 D 금지**
- **E 3일 연속 금지**
- **4일 중 E 3회 금지**
- **최대 연속 근무일수**
- **연속 7일 최대 근무수**
- **D 3일 연속 금지**

규칙을 너무 강하게 설정하면 스케줄이 불가능해질 수 있습니다.

---

## 8. Grade 인력 구성

Grade는 경력/숙련도를 나타내는 숫자로 사용할 수 있습니다.

### 필수 규칙

예: 고년차 기준 Grade = 3, 한 Duty 고년차 최소 인원 = 1  
→ 모든 D/E/N Duty마다 Grade 3 이상 간호사가 최소 1명 있어야 합니다.

### 초저년차 최대 인원

이것도 **필수 규칙**입니다.

예: 초저년차 기준 Grade = 1, 한 Duty 초저년차 최대 인원 = 1  
→ 같은 날짜의 같은 D/E/N에 Grade 1 이하 간호사가 2명 이상 들어갈 수 없습니다.

`최대 인원 = 0`이면 이 제한을 사용하지 않습니다.

### 저년차 권장 인원

저년차 권장 인원은 필수 규칙이 아닙니다. 가능한 범위에서 저년차가 한 Duty에 몰리지 않도록 분산할 때 사용합니다.

---

## 9. 직전 5일 스케줄

이전 달 마지막 5일의 실제 근무를 입력하면 다음 규칙이 월 경계를 넘어 이어집니다.

- N 후 휴무
- N 간격
- E 다음날 D 금지
- 연속근무
- 연속 7일 최대 근무수

직전 5일은 이번 달 총근무수에는 포함되지 않습니다.

---

## 10. 필수 규칙 사전검사

필수 규칙 검사 결과를 평소 화면에 계속 보여주지는 않습니다.

### 설정을 저장했을 때

저장 직후에는 빠르게 확인할 수 있는 기본 충돌만 검사합니다.

예:
- 최소 N근무수가 최대 N근무수보다 큼
- 고정 N이 최대 N근무수보다 큼
- 고정 총근무수가 최대 근무수보다 큼
- 전체 근무수 상한이 날짜별 최소 인원 합보다 작음

문제가 없으면 작은 완료 알림만 표시됩니다.  
충돌이 있으면 그때만 상세 표가 나타납니다.

### 스케줄 생성을 눌렀을 때

화면 맨 위에 **필수 규칙 정밀 검사 중** 메시지가 먼저 나타납니다.

이 단계에서는 개인별로 다음 내용까지 확인합니다.

- 고정 총근무수를 실제로 달성할 수 있는지
- 최소 / 최대 N근무수를 지킬 수 있는지
- 직전 5일의 N과 이번 달 초반 규칙이 충돌하는지
- N 후 휴무 / N 간격
- E 다음날 D 금지
- 최대 연속 근무
- 연차 / 근무불가와 필수근무의 충돌

충돌이 없으면 별도의 큰 성공 박스를 남기지 않고 곧바로 **CP-SAT 근무표 탐색 중**으로 넘어갑니다.

충돌이 있을 때만 상세 내용과 수정 제안을 화면에 표시하고 근무표 탐색을 시작하지 않습니다.


---

## 11. 스케줄 생성 중 표시

생성 중에는 화면 맨 위에 상태가 표시됩니다.

- 필수 규칙 확인 중
- CP-SAT 근무표 탐색 중
- 결과 후처리 중

CP-SAT 탐색 중에는 **남은 탐색시간이 초 단위로 표시**되고 진행 막대도 함께 줄어듭니다.

결과 화면에서는 사전검사 / CP-SAT / 후처리 / 전체 실행시간을 따로 확인할 수 있습니다.

---

## 12. 탐색시간은 얼마나 주면 되나요?

약 37명 규모라면:

- 간단한 테스트: **1~3분**
- 실제 월 근무표: **5~10분**
- `UNKNOWN`이 반복되는 복잡한 달: **15~20분**

최대 20분까지 설정할 수 있습니다.

### `INFEASIBLE`
필수 규칙을 모두 만족하는 해가 없다고 solver가 판정한 경우입니다. 탐색시간을 늘리기보다 충돌하는 규칙을 수정해야 합니다.

### `UNKNOWN`
제한 시간 안에 feasible 해를 찾지 못했다는 뜻입니다. **해가 없다고 판정한 것이 아닙니다.** 탐색시간을 늘려볼 수 있습니다.

---

## 13. 결과 읽기

결과표에는 각 간호사의 D/E/N 배정과 총근무수가 표시됩니다.

Duty 결과에서는 다음을 확인할 수 있습니다.
- 최소 필요 인원
- 실제 배정 인원
- Ideal
- 최소보다 추가된 인원
- Ideal 미충족 / 초과

Solver의 세부 점수는 일반 사용에는 필요하지 않으므로 **고급 정보** 안에서 확인할 수 있습니다.

---

## 14. 기억하면 좋은 세 가지

**1. 최소 인원은 반드시 지켜야 합니다.**  
**2. Ideal은 추가근무가 생겼을 때 어디에 넣을지를 정하는 선호값입니다.**  
**3. 고정 총근무수가 있으면 그 숫자는 정확히 지켜야 합니다.**

## V12.9 UI 변경: 필수 규칙 검사는 필요할 때만 표시

- 평소 화면의 `0차 Hard rule 사전검사` 상시 박스를 제거했습니다.
- 설정 저장 직후에는 빠른 기본 충돌만 한 번 확인합니다.
- 정상이라면 작은 알림만 나타나고 화면을 차지하지 않습니다.
- 스케줄 생성 시에는 화면 상단에서 정밀 검사를 실행합니다.
- 정밀 검사 통과 시 성공 박스를 남기지 않고 바로 CP-SAT 탐색 화면으로 넘어갑니다.
- 충돌이 있을 때만 상세 표를 표시합니다.
- 실행시간 표시는 이제 실제 solve-time 정밀검사 소요시간을 사용합니다.
