# 간호사 D / E / N 근무표 자동편성 사용법

이 프로그램은 한 달의 **D(낮) / E(저녁) / N(밤) 근무표**를 자동으로 만드는 도구입니다. 프로그래밍 지식은 필요하지 않습니다. 간호사별 월 근무수와 제한, 날짜별 최소 인원만 입력하면 됩니다.

---

## 1. 가장 중요한 원칙

스케줄러는 먼저 **반드시 지켜야 하는 조건**을 만족시키고, 그 안에서 가능한 한 균형 좋은 근무표를 찾습니다.

반드시 지키는 조건에는 날짜별 최소 D/E/N 인원, 고정 총근무수, 최대 근무수, 최소/최대 N근무수, 연차·OFF 요청, N 후 휴무, E 다음날 D 금지, 최대 연속근무, Grade별 필수 인원 등이 있습니다.

그 다음에는 Ideal 인원, D/E/N 균형, 휴일근무 균형, 저년차 분산 같은 **권장사항**을 가능한 범위에서 맞춥니다.

---

## 2. 고정 총근무수와 D/E/N 균형

### 모든 간호사에게 고정 총근무수를 입력한 경우

`고정 총근무수`는 **이번 달 실제 D/E/N 근무수**입니다. 이 값이 개인별 D/E/N 균형의 기준이 됩니다.

예를 들어:

- A 간호사: 고정 총근무수 21
- B 간호사: 고정 총근무수 21
- C 간호사: 장기휴가로 고정 총근무수 7

C에게 21근무자와 같은 D/E/N 개수를 요구하지 않습니다. 스케줄러는 **7근무자는 7근무에 맞게, 21근무자는 21근무에 맞게** D/E/N 목표를 자동으로 계산합니다.

예를 들어 전체적으로 D/E/N 비율이 약 40% / 35% / 25%라면:

- 21근무자 → 약 D 8.4 / E 7.4 / N 5.3을 중심으로 균형
- 7근무자 → 약 D 2.8 / E 2.5 / N 1.8을 중심으로 균형

실제 결과는 정수이고, 개인별 최소/최대 N, 고정 D/E/N, 근무 요청과 날짜별 인원 조건 때문에 조금 달라질 수 있습니다.

### 고정 총근무수가 비어 있는 사람이 있는 경우

고정 총근무수가 있는 사람의 근무량을 먼저 반영한 뒤, **날짜별 최소 staffing을 채우기 위해 남은 근무량**을 고정 총근무수가 없는 사람들에게 나누어 자동 총근무 목표를 만듭니다.

그 자동 총근무 목표를 기준으로 각 사람의 D/E/N 균형도 계산합니다.

---

## 3. x와 a의 의미

### x = 원하는 OFF

`x`는 **원래 받을 OFF 중 어느 날짜를 쉬고 싶은지 지정**하는 값입니다.

따라서 x가 많아져도 개인의 총근무 목표나 D/E/N balance 목표를 자동으로 줄이지 않습니다. 단지 그 날짜에는 근무를 배정하지 않습니다.

### a = 연차

`a`는 **연차 날짜**입니다. 해당 날짜에는 근무를 배정하지 않습니다.

간호사용에서는 a도 D/E/N balance 목표를 자동으로 줄이지 않습니다. 실제로 몇 근무를 해야 하는지는 `고정 총근무수`에 직접 입력합니다.

예를 들어 기준 working day가 22일이고 연차를 1일 사용해서 실제 근무가 21일이어야 한다면:

- `고정 총근무수 = 21`
- `a = 1일`

결과에서 `Total + 연차 = 21 + 1 = 22`인지 확인하면 됩니다.

`x`는 이 검산값에 더하지 않습니다.

---

## 4. Duty 설정: 최소 인원과 Ideal

### 최소 D / E / N

각 날짜에 **반드시 필요한 최소 인원**입니다. 최소보다 적게 배정할 수 없습니다.

`0`이면 해당 Duty는 닫혀 아무도 배정하지 않습니다.

### Ideal D / E / N

Ideal은 **추가근무가 생겼을 때 우선적으로 채우고 싶은 인원수**입니다. 화면에서는 주황색 칸으로 표시되며 `+ / −`로 조절할 수 있습니다.

예:

- 최소 D = 7
- Ideal D = 8

추가 인원을 D에 넣어야 한다면 8명까지 채우는 방향을 선호합니다.

**Ideal을 입력했다고 전체 근무수가 늘어나는 것은 아닙니다.** 이미 필요한 추가근무가 어디에 들어갈지를 정하는 기준입니다.

추가근무가 여러 개 필요한 경우 D/E/N balance 계산도 Minimal만 보지 않고 **Ideal이 어느 shift에 추가 인원을 원하는지**를 함께 반영합니다.

---

## 5. 월 근무수 설정

| 항목 | 의미 | 빈칸이면 |
|---|---|---|
| **고정 총근무수** | 이번 달 실제 D+E+N 총근무수를 정확히 고정 | 자동 배정 |
| **최대 근무수** | 월 총근무수 상한 | 제한 없음 |
| **최소 N근무수** | N근무 하한 | 제한 없음 |
| **최대 N근무수** | N근무 상한 | 제한 없음 |
| **고정 D / E / N** | 해당 shift의 정확한 월 개수 | 자동 배정 |

예:

`고정 총근무수=18`, `최소 N근무수=3`, `최대 N근무수=5`

→ 총 18근무를 정확히 하면서 N은 3~5개가 되어야 합니다.

`고정 N=4`

→ N은 정확히 4개입니다.

### 내부 shift_adj

일반 간호사용 화면에서는 `shift_adj`를 표시하지 않습니다. 현재 D/E/N 균형은 고정 총근무수 또는 자동 계산된 총근무 목표를 직접 기준으로 계산하므로 일반 사용자가 따로 계산할 필요가 없습니다.

기존 Excel/이전 버전 호환을 위해 수동으로 저장된 값이 있을 때만 내부 **soft balance 미세 보정값**으로 남겨두었습니다. `fixed_Total`의 정확한 근무수를 바꾸지는 않습니다.

---

## 6. 근무 요청 기호

- **D / E / N**: 반드시 원하는 근무
- **d / e / n**: 해당 근무는 불가
- **x**: 원하는 OFF
- **a**: 연차
- 빈칸: 특별한 요청 없음

대문자 요청, x, a는 필수 조건으로 처리되므로 다른 필수 규칙과 직접 충돌하면 사전검사에서 알려줍니다.

---

## 7. 개인 근무 패턴 규칙

각 항목 이름에 마우스를 올리면 자세한 설명을 볼 수 있습니다.

주요 규칙은 하루 최대 근무 종류 수, 연속 N 최대, N 종료 후 휴무일, 다음 N까지 간격, E 다음날 D 금지, E 3연속 금지, 4일 중 E 3회 금지, 최대 연속 근무일수, 연속 7일 최대 근무수, D 3연속 금지입니다.

규칙을 너무 강하게 설정하면 스케줄이 불가능해질 수 있습니다.

---

## 8. Grade 인력 구성

Grade는 경력/숙련도를 나타내는 숫자입니다.

**필수 규칙** 예: 고년차 기준 Grade 2, 한 Duty 고년차 최소 1명 → 모든 D/E/N에 Grade 2 이상 간호사가 최소 1명 필요합니다.

**초저년차 최대 인원**도 필수 규칙입니다. 예를 들어 Grade 1 이하 최대 1명이면 같은 날짜·같은 Duty에 초저년차가 2명 이상 들어갈 수 없습니다. 최대 인원 0이면 이 제한을 사용하지 않습니다.

**저년차 권장 인원**은 필수 조건이 아니라, 가능한 범위에서 저년차가 한 Duty에 몰리지 않도록 하는 선호값입니다.

---

## 9. 직전 5일 스케줄

이전 달 마지막 5일을 입력하면 N 후 휴무, N 간격, E 다음날 D 금지, 연속근무, 연속 7일 최대 근무수 같은 규칙이 월 경계를 넘어 이어집니다.

직전 5일은 이번 달 총근무수에는 포함되지 않습니다.

---

## 10. 필수 규칙 사전검사

평소 화면에는 큰 검사 박스를 계속 표시하지 않습니다.

설정을 저장했을 때는 빠르게 확인할 수 있는 기본 충돌만 검사하고, 문제가 없으면 작은 완료 알림만 보여줍니다.

스케줄 생성을 누르면 화면 맨 위에서 **필수 규칙 정밀 검사**를 먼저 실행합니다. 고정 총근무수 달성 가능성, 최소/최대 N, 직전 5일, N 휴식/간격, 연속근무, 연차·OFF와 필수근무 충돌 등을 확인합니다.

충돌이 없으면 바로 CP-SAT 근무표 탐색으로 넘어가고, 충돌이 있을 때만 상세 내용과 수정 제안을 표시합니다.

---

## 11. 스케줄 생성과 탐색시간

생성 중에는 화면 맨 위에 현재 단계가 표시됩니다.

- 필수 규칙 정밀 검사 중
- CP-SAT 근무표 탐색 중
- 결과 후처리 중

CP-SAT 단계에는 남은 탐색시간이 표시됩니다.

약 37명 규모에서는 보통 5~10분 정도를 먼저 사용하고, `UNKNOWN`이 반복되는 복잡한 달은 15~20분까지 늘려볼 수 있습니다.

- **INFEASIBLE**: 필수 규칙을 모두 만족하는 해가 없다고 판정
- **UNKNOWN**: 제한 시간 안에 해를 찾지 못했을 뿐, 해가 없다는 뜻은 아님

## 12. 결과 확인

결과표의 `Total`은 실제 D/E/N 근무수입니다. `Total+연차`는 `Total + a`로 계산되는 검산값입니다.

예: `Total=21`, `연차=1` → `Total+연차=22`

`최대 근무수`, `최소 N근무수`, `최대 N근무수`는 설정/검증용 값이므로 최종 근무 통계표에서는 숨깁니다.

Duty 결과에서는 최소 필요 인원, 실제 배정 인원, Ideal, 추가 배정 인원, Ideal 미충족/초과 등을 확인할 수 있습니다.

Solver의 세부 점수는 일반 사용에는 필요하지 않으므로 고급 정보 안에서만 표시합니다.

## 13. 기억하면 좋은 네 가지

1. **고정 총근무수는 실제 이번 달 근무수이며 D/E/N balance의 기준입니다.**
2. **x와 a는 쉬는 날짜를 정하지만 balance 목표를 자동으로 줄이지 않습니다.**
3. **Ideal은 추가근무가 어디에 들어갈지를 정하는 선호값입니다.**
4. **장기휴가처럼 총근무수가 크게 다른 사람도 그 사람의 고정 총근무수에 맞춰 D/E/N 목표가 자동으로 작아집니다.**

## V12.15: 탐색 정체 시 선택적 자동 조기 종료

사이드바의 **탐색 정체 시 자동 종료 (선택)**을 켠 실행에서만 동작합니다.

Feasible 근무표를 이미 찾은 이후의 Placement / Quality 최적화에서:

- 현재까지의 가장 좋은 목적함수 점수
- CP-SAT의 best objective bound

가 선택한 시간 동안 **둘 다 개선되지 않으면** 탐색 효율이 정체된 것으로 판단하고,
최대 탐색시간이 남아 있어도 현재까지의 가장 좋은 feasible 근무표를 반환합니다.

기본 정체시간은 60초이며 30~300초에서 선택할 수 있습니다.

### 탐색 효율 그래프

이 옵션을 켠 실행은 결과의 **📉 탐색 효율 보기**에서:

- 시간에 따른 현재 최선 점수
- 최적 가능 경계(best bound)
- Quality 단계의 k / k1 / k2 / k3 / k4
- k 단순합

을 확인할 수 있습니다.

초반에 점수가 빠르게 낮아진 뒤 긴 시간 동안 평평하다면,
다음 달에는 최대 탐색시간을 더 짧게 설정해도 비슷한 품질의 근무표를 얻을 가능성이 높습니다.

반대로 마지막까지 점수가 계속 개선된다면 더 긴 탐색시간이 실제로 도움이 될 수 있습니다.

조기 종료는 **feasible 해를 이미 찾은 이후**에만 동작합니다.
따라서 hard-rule feasibility 탐색을 중간에 포기하는 기능은 아닙니다.

Excel 결과에도 `SearchProgress`와 `SearchStop` sheet가 추가됩니다.

## V12.16: 같은 Quality 점수 안에서 개인별 D/E 편차 총합 최소화

일부 중간 연차 간호사가 `9D/3E`, `3D/11E`처럼 D/E 한쪽으로 크게 치우치는 현상을 줄이기 위한
**추가 soft refinement 단계**를 넣었습니다.

기존 `k`는 전체 간호사의 D/E 편차에서 가장 큰 하방/상방 폭을 제한하는 envelope 역할을 합니다.
따라서 이미 최악 편차 폭이 정해진 뒤에는 다른 간호사가 그 범위 안에서 움직여도 `k`가 더 커지지 않을 수 있습니다.

V12.16은 기존 우선순위를 바꾸지 않습니다.

1. Hard rules
2. 필요한 extra 수
3. Ideal / 추가근무 분산
4. 기존 Quality (`k/k1/k2/k3/k4`, Junior/Grade 등)
5. **기존 Quality 점수를 고정한 뒤 개인별 D/E 편차 총합 최소화**

즉 5단계는 기존 Quality를 희생해서 D/E를 예쁘게 만드는 것이 아닙니다.
**동일한 기존 Quality 수준을 만족하는 해들 중에서** 각자의 workload 기반 D/E 목표에 더 가까운 해를 선택합니다.

개인 D/E 목표는 `fixed_Total` 또는 자동 계산된 개인 total target을 기준으로 합니다.
예를 들어 장기휴가로 `fixed_Total=7`인 사람은 7근무에 맞는 D/E 목표를 사용하고,
`fixed_Total=21`인 사람은 21근무에 맞는 D/E 목표를 사용합니다.

소수점 목표(예: D=6.4)는 6~7을 정상 범위로 보고, 그 범위를 벗어난 정도만 편차로 계산합니다.
사용자가 `fixed_D` 또는 `fixed_E`를 직접 지정한 경우 해당 shift는 이 추가 soft penalty에서 제외합니다.

탐색 정체 자동 종료 옵션을 켠 경우 `de_refine` 단계도 탐색 효율 기록에 포함됩니다.

## V12.17: 탐색 효율 상세표 중복 컬럼 오류 수정

V12.16의 `de_refine` 탐색 효율 표에서:

- `objective`
- `de_individual`

두 값이 모두 `개인 D/E 편차 총합`이라는 같은 표시명으로 변환되면서
PyArrow가 `Duplicate column names` 오류를 발생시키던 문제를 수정했습니다.

`de_refine` 단계에서는 objective 자체가 이미 개인 D/E 편차 총합이므로
동일한 `de_individual` 컬럼을 중복 표시하지 않습니다.

또한 향후 컬럼명이 겹치더라도 결과 화면 전체가 중단되지 않도록
표시 직전에 중복 컬럼을 제거하는 안전장치를 추가했습니다.

Solver 계산 로직과 V12.16의 D/E refinement 우선순위는 변경하지 않았습니다.

## V12.18: 전체 탐색시간 표시 + 최종 실제 편차 재계산

### 왜 20분 실행인데 탐색 표에는 36초만 보였나요?

V12.17의 탐색 효율 표에서 `초`는 **마지막 optimization 단계 안에서의 경과시간**이었습니다.

예를 들어 20분 최대 탐색에서 앞 단계인:

1. feasibility / extra
2. Ideal·추가근무 배치
3. Quality (`k/k1/k2/k3/k4`)
4. D/E 미세조정

순서로 진행되므로, D/E 미세조정이 전체 탐색 약 18~19분 후에 시작되어
그 단계에서 36초 만에 최적값을 찾을 수 있습니다.

V12.18부터 그래프 x축은 **전체 CP-SAT 경과시간**을 사용하고,
상세표에는 `전체 경과초`와 `단계 내 초`를 둘 다 표시합니다.

### 왜 개인 D/E 편차 총합은 0인데 k D/E는 6처럼 보일 수 있었나요?

기존 `k` 계열은 Quality 단계의 soft auxiliary variable입니다.
뒤의 D/E refinement 단계에서 목적함수가 바뀐 뒤에는 이 보조변수가 실제 최종 배정의
최소 편차와 정확히 같지 않은 느슨한 값으로 남을 수 있었습니다.

V12.18부터 결과 화면의 최종 편차는 **실제 완성된 근무표에서 다시 계산**합니다.

- 실제 D/E 편차
- 실제 휴일 편차
- 실제 총근무 편차
- 실제 N 편차
- 실제 Grade 편차
- 실제 Junior 초과
- 최종 실제 balance penalty / 전체 quality penalty

따라서 마지막 미세조정으로 D/E가 모두 개인 workload 목표 범위 안에 들어오면
`실제 D/E 편차 = 0`, `개인 D/E 편차 총합 = 0`으로 일관되게 표시됩니다.

또 D/E 미세조정은 이전 Quality 점수를 `=`로 고정하지 않고,
**이전 점수보다 나빠지지 않는(`<=`) 범위**에서 수행하도록 수정했습니다.
그래서 미세조정 과정에서 더 좋은 전체 Quality 해를 발견하면 그대로 사용할 수 있습니다.

## V12.19: Plateau 표시와 전체 탐색시간 진단 보강

V12.18에서 그래프 x축을 전체 CP-SAT 경과시간으로 바꾼 데 이어,
V12.19에서는 **왜 20분을 돌렸는데 마지막 표에는 수십 초만 보이는지**를 바로 확인할 수 있도록
단계별 시간 기록을 추가했습니다.

### 탐색 단계별 시간

결과의 **`⏱ 탐색 단계별 시간 보기`**에서 다음을 확인할 수 있습니다.

- 각 단계 시작 시점(전체 CP-SAT 초)
- 종료 시점
- 실제 사용시간
- Solver status
- 종료 이유
- 마지막 objective
- 마지막 best bound
- objective-bound gap

예를 들어 마지막 D/E 미세조정 표가 10~36초라고 보여도,
단계별 표에서 `시작(전체초)=1130`이라면 실제로는 전체 20분 탐색의 마지막 구간이라는 뜻입니다.

### Plateau 그래프 정확도 개선

이전 버전은 **새로운 feasible 해가 좋아질 때만** progress row를 주로 기록했습니다.
따라서 실제로는 best bound가 계속 개선되어 solver가 최적성을 증명하고 있는데도
그래프가 평평해 보일 수 있었습니다.

V12.19는:

- incumbent(현재 최선 해) 개선
- best bound 개선
- final 상태

를 구분하여 기록합니다.

best-bound 변화는 로그가 너무 커지지 않도록 약 1초 간격으로 제한합니다.

### Plateau 종료 기준

OR-Tools가 best-bound callback을 지원하는 경우:

1. feasible 해가 이미 존재하고
2. incumbent가 설정 시간 동안 개선되지 않고
3. best bound도 설정 시간 동안 개선되지 않을 때

조기 종료합니다.

즉 **해도 좋아지지 않고, 최적성 증명도 진전되지 않는 구간**을 plateau로 봅니다.

best-bound callback을 지원하지 않는 오래된 OR-Tools에서는
incumbent 개선만으로 보수적으로 판단합니다.

### 다음 실행시간 결정

- `OPTIMAL/단계 완료`로 빨리 끝난 단계 → 시간을 더 줄 필요가 큼
- `plateau`로 끝난 단계 → 비슷한 입력에서 시간을 더 늘릴 이득이 작을 가능성
- `할당시간 종료` + 마지막까지 objective/bound 개선 → 더 긴 시간이 도움될 가능성
- 가장 긴 단계가 어디인지 먼저 확인한 뒤 최대 탐색시간을 조정하는 것이 좋습니다.

Excel에는 `SearchStages` sheet도 추가됩니다.

## V12.20 추가 기능 — Hard 원인 찾기 / Grade 직접 입력 / 병동 Team제

### 1) Hard coding 사전검사 강화

스케줄 생성 전 검사에서 단순히 `해 없음`만 표시하지 않고 다음과 같은 **확정 충돌**을 가능한 한 구체적으로 표시합니다.

- 특정 날짜·Duty에서 `a`, `x`, 소문자 불가요청, 다른 Duty 고정 때문에 후보 인원이 Minimal보다 부족한 경우
- 개인 `fixed_Total`이 개인 hard rule 아래에서 정확히 달성 불가능한 경우
- 전체 `fixed_Total / maximum_total` 상한 합이 Duty 최소 필요량보다 작은 경우
- Grade 고년차/초저년차 hard rule 때문에 특정 날짜·Duty를 채울 수 없는 경우
- Team 1/2를 사용하는 경우 특정 Team의 후보 부족 또는 팀별 전체 근무상한 부족

전체 solver가 그래도 `INFEASIBLE`을 증명하면 결과 탭에서 상세 병목 진단을 자동 실행합니다.

진단모드의 **정확 구간 진단**은 1/2/3/5/7일 및 월 전체 구간에 대해,
직전 근무표·N 후 휴무·연속 7일 상한·월 고정근무수·구간 밖 고정 요청까지 적용한
개인별 최대 근무수를 CP-SAT로 계산합니다. 그 합계보다 필요 근무수가 많으면
확정 부족 구간과 부족 수, 개인별 최대 및 적용 조건을 표시합니다.
예를 들어 `11/01~11/02 필요 12근무, 개인 최대 합계 11근무`이면 탐색시간을 늘려도 해결되지 않습니다.

첫 확정 부족 구간을 찾으면 멈추며, 계산 예산은 기본 30초입니다.
시간 내 최적값을 증명하지 못한 개인 계산은 부족 판정에 사용하지 않습니다.
부족을 찾지 못해도 전체 배치가 가능하다는 뜻은 아닙니다.
표의 요청과 규칙을 검토해 조정한 뒤 다시 생성하여 전체 월간 해를 확인하세요.

### 2) Grade와 Team을 앱에서 직접 수정

Excel을 열지 않아도 사이드바의 간호사 `수정` 버튼 또는 `개인별 Grade & 근무 규칙 설정`에서 Grade와 Team을 직접 바꿀 수 있습니다.

### 3) 선택적 병동 Team제

각 간호사의 Team은 다음과 같습니다.

- `미지정`: Team 규칙 사용 안 함 / Team 최소인원에 포함되지 않음
- `1팀`
- `2팀`

**1팀과 2팀이 모두 한 명 이상 설정된 경우에만** Team hard rule이 활성화됩니다.

각 날짜·Duty의 `Minimal = m`일 때 각 Team에서 최소 `floor(m/2)`명을 배치합니다.

- Minimal 2 → 1팀 ≥ 1, 2팀 ≥ 1
- Minimal 3 → 1팀 ≥ 1, 2팀 ≥ 1, 나머지 1명은 Team 상관없이 가능
- Minimal 4 → 1팀 ≥ 2, 2팀 ≥ 2
- Minimal 5 → 1팀 ≥ 2, 2팀 ≥ 2, 나머지 1명은 자유

Team을 모두 미지정하면 기존 응급실 스케줄과 동일하게 작동합니다.

Scheduler API: `2026-08-28-v12.20-hardcheck-grade-team`

## V12.21 — 동적 Multi-Team 병동 지원

V12.20의 1팀/2팀 고정 구조를 제거하고, **실제로 간호사가 배정된 Team 번호를 자동 인식**합니다.

- 앱에서 `미지정`, `1팀` ~ `10팀`까지 선택 가능
- 실제로 사람이 존재하는 Team만 `활성 Team`으로 계산
- 활성 Team이 0~1개이면 Team hard rule 비활성화
- 활성 Team이 2개 이상이면 Team hard rule 자동 활성화

활성 Team 수를 `T`, 해당 날짜·Duty의 Minimal을 `m`이라고 하면:

`각 활성 Team 최소인원 = floor(m / T)`

나머지 인원은 어느 Team에서 와도 되는 `alpha`입니다.

예시:

- 3팀제: Minimal 3 → 1/1/1
- 3팀제: Minimal 4 → 1/1/1 + alpha 1
- 3팀제: Minimal 6 → 2/2/2
- 4팀제: Minimal 4 → 1/1/1/1
- 4팀제: Minimal 5 → 1/1/1/1 + alpha 1
- 4팀제: Minimal 8 → 2/2/2/2

`Minimal < 활성 Team 수`인 경우 `floor(m/T)=0`이므로 특정 Team을 임의로 강제하지 않습니다.

Hard coding 사전검사와 INFEASIBLE 진단도 동일한 동적 Team 공식을 사용합니다.

Scheduler API: `2026-08-28-v12.21-dynamic-teams`
